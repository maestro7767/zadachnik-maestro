# Модули приложения «Маэстро»

Этап 1: выделение модулей из одного файла и тесты расчётов. Интерфейс пока остаётся в исходном `index.html`.

## src/core/types.ts
Типы `Category`, `Plan` и названия отделов. Не содержит логики.

## src/core/date.ts
Работа с датами в формате YYYY-MM-DD: разбор и форматирование, сдвиг на дни, неделя с понедельника, сетка месяца для календаря.
Функции принимают даты параметрами, поэтому их легко тестировать.

## src/core/stats.ts
Процент выполнения (общий и по отделу), серия дней подряд, недельная статистика по дням.
Серия не обнуляется до конца дня: пока сегодня ничего не отмечено, отсчёт идёт от вчера.

## src/assistant/parse.ts
Разбор фразы помощника: отделяет дату и время от текста задачи.
Принимает `today` параметром, поэтому результат не зависит от текущего дня и тестируется стабильно.
Ограничение: `в 5` без уточнения переводится в 05:00.

## tests/
Автотесты на `node:test`. Запуск: `npm test`.
Скрипт использует флаг `--experimental-strip-types` (Node 22.6+), поэтому зависимости для тестов не нужны.

## Что дальше
Следующий шаг этапа: выделить модули данных (хранение в localStorage, миграции) и уведомлений, затем перенести интерфейс.

## src/data/model.ts (шаг 1)
Типы хранимых данных: `AppData`, `UserData`, `Profile`, проверка плана `isPlan`.
Версия формата `SCHEMA_VERSION` = 1. Новые поля делать необязательными, а при изменении структуры поднимать версию и добавлять миграцию.

## src/data/storage.ts (шаг 1)
Загрузка и сохранение через интерфейс `KeyValueStore` (в браузере — localStorage, в тестах — память).
`migrate` приводит данные любой версии к текущей и отбрасывает испорченные планы. Испорченный JSON не ломает загрузку: возвращается пустое состояние.
`saveAppData` возвращает `false`, если хранилище переполнено, и не падает.

## src/notifications/reminders.ts (шаг 1)
Чистая логика выбора напоминаний: `dueReminders` возвращает планы, время которых наступило, и обновлённый список уже напомненных, чтобы не повторять уведомление.
Сама отправка уведомления (`Notification` в браузере) остаётся в интерфейсе, а не в этом модуле.

## Сборка (шаг 2, часть 1)
- `index.html` в корне: текущая страница приложения без изменений. Vite не трогает её встроенные скрипты.
- `public/`: манифест и иконки. Vite копирует их в корень `dist/` как есть.
- `vite.config.ts`: `base: "./"`, чтобы сборка работала в подпапке GitHub Pages.
- Команда `npm run build` создаёт папку `dist/`, которую можно открыть или выложить на хостинг.

Перенос кода в `src/` и подключение модулей `src/data` и `src/notifications` — следующая часть шага 2.

## Подключение модулей к странице (шаг 2, часть 2)
- Основной скрипт `index.html` стал модулем (`type="module"`) и импортирует `loadAppData` и `saveAppData` из `src/data/storage.ts`.
- Загрузка данных идёт через `migrate`: испорченные планы отбрасываются, старый формат без версии приводится к текущему.
- Сохранение идёт через `saveAppData`: при переполнении localStorage приложение не падает.
- Ключ `zadachnik-v1` и структура данных не менялись, поэтому уже сохранённые планы и профили должны открыться без потерь.

## Напоминания на странице (шаг 3)
- Функция `checkReminders` в `index.html` использует `dueReminders` и `nowParts` из `src/notifications/reminders.ts`.
- Выбор планов для напоминаний больше не дублируется в интерфейсе: правила совпадают с тестами.
- Системное уведомление показывается только при разрешении браузера. Пока страница открыта, проверка идёт каждые 30 секунд.

## Линтер (шаг 3)
- `eslint.config.js` — конфигурация ESLint для TypeScript (через `typescript-eslint`).
- Команда `npm run lint` проверяет `src/` и `tests/`. Требует `npm install`.

## src/data/transfer.ts (шаг 4: экспорт и импорт)
- `buildExport` собирает JSON-файл для одного аккаунта: планы и заметки. Профиль, аватарка, фон и пароли не выгружаются.
- `mergeImport` проверяет файл (метка формата, версия, структура) и добавляет только новые планы. Существующие планы не перезаписываются, заметка заполняется, только если локальная пуста.
- Файл из более новой версии приложения отклоняется, чтобы не потерять данные.

Кнопки «Скачать» и «Выбрать» находятся в профиле, в разделе «Конфиденциальность». Кнопка «Скачать» работает в браузере, файл сохраняется в папку загрузок.

## Визуальный слой (шаги анимации и оформления)
- Анимация отметки: галочка «пружинит», текст плавно приглушается.
- Пустые состояния: значок ✦ над подсказкой и плавное появление.
- Шапка: мягкое свечение в цвете выбранного акцента, плавная смена при изменении цвета.
- Нажатия: кнопки и карточки немного уменьшаются при касании.
- Таймлайн: планы дня стоят на вертикальной линии с точками цвета категории.
Не сделано: движущаяся линия «сейчас» и анимация открытия шторок. Первую нужен таймер, вторая перерисовывает экран при каждом действии и мерцала бы.

## Синхронизация выбранного дня (шаг оформления)
- Полоса дат и график недели берут неделю и подсветку от выбранного дня (`ui.anchor`), а не от сегодняшнего.
- Выбранный день в полосе и на графике подсвечивается одинаково.

# Этап «восстановление из бандла»: все модули в src/

Страница `index.html` больше не содержит копий логики: она импортирует модули из `src/`,
которые восстановлены из собранного бандла с возвращением типов.

## src/gamification/
- `xp.ts` — опыт за планы, пороги уровней, прогресс до следующего уровня.
- `challenges.ts` — испытания дня: три детерминированных испытания по дате, одинаковы для всех.
- `total.ts` — суммарный опыт из планов и выполненных испытаний; отдельно опыт не хранится.
- `streaks.ts` — серия дней с заморозкой: один пропуск в неделю не обнуляет серию. Награды за серии.

## src/habits/
- `habits.ts` — тип привычки, отметка дня (иммутабельно), серия привычки с заморозкой.
- `starter.ts` — нейтральный стартовый набор привычек.

## src/sport/
- `workouts.ts` — подходы (вес × повторения), лимиты, объём тренировки, прогресс по упражнению.
- `restTimer.ts` — таймер отдыха по меткам времени: не сбивается при свёрнутом приложении.

## src/study/
- `model.ts` — типы учебных данных: предметы, работы, расписание, дедлайны, карточки.
- `lessons.ts` — занятия на дату (понедельник — 1).
- `deadlines.ts` — дни до срока и ближайшие дедлайны.
- `pomodoro.ts` — цикл 25/5, длинный отдых после четвёртой работы; состояние от времени старта.
- `flashcards.ts` — интервальное повторение по коробкам Лейтнера (1, 3, 7, 14, 30 дней).
- `grades.ts` — оценки: школа (средневзвешенный 2–5), колледж (100 + до 20 за посещаемость), вуз (БРС).
- `journal.ts` — итог по предмету для выбранного заведения, нейтральные тексты следующих шагов.
